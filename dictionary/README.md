# STC 词表

词表由三部分组成：

| 文件 | 内容 |
|---|---|
| [`recommended.yaml`](recommended.yaml) | 推荐词：每个词只有一个意思，并写明和近义词的区别 |
| [`avoid.yaml`](avoid.yaml) | 不推荐写法：常见的含糊词、套话和句式，附推荐写法 |
| [`terms.example.yaml`](terms.example.yaml) | 项目术语表模板：每个项目按自己的产品填写 |

规则里怎么用词表，见通用规则 G2、G3（[`rules/general.md`](../rules/general.md)）。

## 推荐词的格式

```yaml
- word: 删除
  pos: 动词
  meaning: 把对象永久去掉，之后不能恢复
  not_same_as:
    移除: 从一组对象里拿出来，对象本身还在
    清空: 去掉一个容器里的全部内容，容器还在
  example: 删除这份报告后，报告不能恢复。
  profiles: [web-dev, document]
```

| 字段 | 含义 | 必填 |
|---|---|---|
| `word` | 推荐的词 | 是 |
| `pos` | 词性。一个词条只定一个词性 | 是 |
| `meaning` | 这个词在 STC 里唯一的意思 | 是 |
| `not_same_as` | 容易混用的近义词，以及每个近义词的意思 | 否 |
| `example` | 用法例句 | 是 |
| `profiles` | 主要适用的档位；不写表示所有档位 | 否 |

## 不推荐写法的格式

```yaml
- avoid: 进行 + 动作名词
  type: 虚动词
  why: 句子变长，动作藏进了名词
  use: 直接写动词
  examples:
    - before: 对数据进行分析。
      after: 分析数据。
```

| 字段 | 含义 | 必填 |
|---|---|---|
| `avoid` | 不推荐的词或句式；有几种写法时用「/」分开 | 是 |
| `type` | 类别，见下表 | 是 |
| `why` | 为什么不推荐 | 是 |
| `use` | 推荐的写法 | 是 |
| `examples` | 改写前后的例句 | 是 |
| `profiles` | 只在这些档位里不推荐；不写表示所有档位 | 否 |

### 类别

| 类别 | 是什么 |
|---|---|
| 虚动词 | 「进行、加以、作出」加名词，代替直接的动词 |
| 程度词 | 「非常、显著、大幅」这类说不清程度的词 |
| 模糊量词 | 「一些、部分、相关」这类说不清数量或范围的词 |
| 含糊动词 | 不带对象和数字时说不清做了什么的动词，如「优化、提升」 |
| 营销词 | 「赋能、一站式、打造」这类不增加信息的宣传用语 |
| 行话 | 「沉淀、落地、对齐、闭环」这类互联网和咨询行业的行话，读者要先翻译成具体动作才懂 |
| 套话 | 删掉之后意思不变的固定说法，如「值得注意的是」 |
| 口号句式 | 对比宣言、对仗金句这类追求气势、不说清事实的句式 |
| 翻译腔 | 从外语长句直译留下的结构，如「基于……的情况下」 |
| 冗余 | 不增加信息的修饰，如「成功地、有效地」 |
| 强度词 | 规则里表示要求强度的非标准写法，只在 instruction 档里不推荐 |
| 人称代词 | 容易指代不清的代词，按档位不推荐 |

## 词条怎么选

词条按真实的 AI 中文输出中的出现次数排定先后，先收出现最多的。例句使用通用名称，不含可识别的个人或企业信息。

## 增加词条

增加词条前，应先检查同一个词是否已经收录。一个词在推荐词表里只能有一个词条。新增的不推荐写法，应附至少一组改写前后的例句。
