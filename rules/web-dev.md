# web dev 档

适用于网页和应用界面上给用户看的文字：按钮、标签、提示、报错、通知、空状态、页面正文。手机应用和桌面应用的界面文字同样适用。

按「谁看」判断是否属于本档：存在数据库里、最终显示给用户的文字（通知模板、标签名）属于本档；服务器日志、代码注释属于 document 档。

通用规则（[`general.md`](general.md)）同样适用。

### W1 不用复数人称代词和第三人称代词

界面文字不应使用复数人称代词和第三人称代词：我们、你们、他们、她们、它们、咱们、大家、他、她、它。要说谁，应写名称。

原因：界面上同时出现用户、用户所在的公司、产品方和其他对象，复数代词指的是哪一群，读者要猜。按钮、提示、报错常常单独出现，第三人称代词找不到所指的词。

- ✗ 账号已停用，请联系我们。
- ✓ 账号已停用，请联系客服。
- ✗ 大家分的是同一块蛋糕。
- ✓ 各品牌分的是同一块蛋糕。
- ✗ 当前账号没有它的查看权限。
- ✓ 当前账号没有这份报表的查看权限。

### W2 「你」指用户，「我」只出现在用户的原话里

「你」应只指正在使用产品的人。「我」应只出现在用户自己说的话里，比如用户输入的原话。「你」和「您」二选一，全站应统一。

- ✗ 诊断我的网站（按钮上的「我」指用户，旁边「联系我们」的「我」又指产品方）
- ✓ 诊断网站

### W3 按钮以动词开头，用推荐的动作词

按钮文字应以动词开头，宜不超过 6 个字。动作词宜使用推荐词表里的词，同一个动作全站应使用同一个词。

说明：推荐词表给删除、移除、清空这类动作词各定了一个意思，见 [`recommended.yaml`](../dictionary/recommended.yaml)。

- ✗ 立即提交审核申请吧
- ✓ 提交审核

### W4 同一个功能在各处同名

同一个功能在导航、标题、按钮、提示和帮助文档里应使用同一个名称。

- ✗ 导航叫「项目」，按钮写「新建工程」。
- ✓ 导航叫「项目」，按钮写「新建项目」。

### W5 报错说清发生了什么、接下来能做什么

报错应说清两件事：发生了什么，用户接下来能做什么。报错不应只给错误代码，不应责怪用户。

- ✗ 操作失败（500）。
- ✓ 保存失败：网络连接中断。检查网络后重试。
- ✗ 你输入错了。
- ✓ 手机号应为 11 位数字。

### W6 空状态说明这里会出现什么、怎么开始

空状态应说明这里会出现什么内容，以及用户怎么开始。

- ✗ 暂无数据。
- ✓ 还没有报告。完成第一次诊断后，报告会出现在这里。

### W7 说明文字讲「是什么、怎么读」，不讲操作

说明文字（悬停提示、信息图标里的文字）应回答「这是什么、怎么读」。怎么操作应由控件本身表达，不应写进说明文字。

- ✗ 点击任意一行可以查看明细。这个数字表示提到你的回答占全部回答的比例。
- ✓ 提到你的回答占全部回答的比例。

### W8 一句界面文字写成一个完整的字符串

一句界面文字应写成一个完整的字符串模板，不应拼接句子片段。

原因：拼接出来的句子，检查脚本和翻译工具都读不到整句；换成其他语言时语序也会出错。

- ✗ `'已选择' + count + '个文件'`
- ✓ `'已选择 {count} 个文件'`
