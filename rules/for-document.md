# for document

适用于给人读的文字：报告、方案、说明、手册、会议纪要，以及给开发者看的代码注释、提交说明和日志。读者读这些文字，是为了理解内容或照着操作。

通用规则（[`for-all.md`](for-all.md)）同样适用。

### D1 主语写名称，不写“我们”“你们”

主语必须写名称：公司名、品牌名、人名或职务。不得写“我们”“你们”“他”“她”“它”。表头和分工表同样适用。主语是作者本人或作者所在的团队时，可以省略主语，比如周报里写“本周上线了导出功能”。

原因：文档会被转发，读的人不一定知道“我们”指谁。

- ✗ 表头：“我们负责”“你们负责”
- ✓ 表头：“供应商负责”“客户负责”

### D2 先写结论，再写依据

必须先写结论，再写依据。每一节的第一句宜写这一节的结论。

- ✗ 本季度共收到 120 条反馈。其中 45 条与加载速度有关……综合来看，加载速度问题要优先处理。
- ✓ 本季度优先处理加载速度问题。依据：120 条反馈里有 45 条与加载速度有关，占 38%。

### D3 一段只讲一个主题

一段必须只讲一个主题，一段宜不超过 6 句。

### D4 三项以上用列表

三项以上的并列内容、三步以上的操作，必须写成列表。操作步骤用编号列表。

### D5 操作步骤一步一个动作，说明与步骤分开

操作步骤必须一步写一个动作，每一步以动词开头。说明和提醒必须与步骤分开写，说明里不得夹带要求。

- ✗ 打开设置并点击账号，修改邮箱，注意新邮箱要能收信。
- ✓
  1. 打开“设置”。
  2. 点击“账号”。
  3. 修改邮箱地址。
  4. 打开新邮箱里的验证邮件，点击验证链接。

  说明：验证完成前，登录仍使用原邮箱。

### D6 风险提示先写动作或条件，再写后果

风险提示必须先写要做的动作或触发的条件，再写不照做的后果。

- ✗ 请注意数据安全。
- ✓ 删除前先导出数据。删除后，数据不能恢复。

### D7 提醒分三级：警告、注意、说明

需要提醒读者的内容，必须按风险大小用三个固定的词开头：

| 词 | 用在什么时候 |
|---|---|
| 警告 | 继续操作可能造成数据丢失、安全问题或无法撤销的结果 |
| 注意 | 继续操作可能失败，或结果不符合预期 |
| 说明 | 补充信息，没有风险 |

- ✗ 温馨提示：删除后无法恢复哦。
- ✓ 警告：删除后，数据不能恢复。

### D8 代码注释写原因，提交说明先写改了什么

代码注释必须写为什么这样做，不得复述代码在做什么。提交说明的第一行必须写改了什么，正文写为什么改。

- ✗ `// 遍历列表`
- ✓ `// 跳过已删除的记录：接口返回的数据里仍包含已删除的记录`
- ✗ 提交说明：“修改了一些问题”
- ✓ 提交说明：“修复导出表格时日期少一天的问题”，正文写原因：时区按 UTC 计算。
