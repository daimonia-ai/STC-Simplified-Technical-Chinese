# for all

通用规则，四个场景都要用。场景规则与通用规则不一致时，以场景规则为准。

## 用词

### G1 一个意思只用一个词

同一份文字里，同一个东西、同一个动作必须只用一个叫法。

原因：同义词换着用，读者会以为说的是几样不同的东西。大模型为了显得用词丰富，常常轮换同义词。

- ✗ 上传前，系统先校验文件格式，检查通过后再核对文件大小。
- ✓ 上传前，系统先检查文件格式，再检查文件大小。

### G2 产品名、功能名、指标名照项目术语表写

项目必须有术语表，写明每个专有名称的叫法和含义。术语表里有的名称，必须照术语表写，不得另造近义叫法。

说明：术语表是项目自己的词典，补充 STC 词表。模板见 [`dictionary/terms.example.yaml`](../dictionary/terms.example.yaml)。

- ✗ 导航里叫“项目”，帮助文档里叫“工程”。
- ✓ 导航和帮助文档都叫“项目”。

### G3 用推荐词，按词表替换不推荐写法

宜使用推荐词表（[`recommended.yaml`](../dictionary/recommended.yaml)）里的词。不推荐写法表（[`avoid.yaml`](../dictionary/avoid.yaml)）里列出的写法，必须按表里的推荐写法替换。

说明：推荐词表给每个词定一个意思；不推荐写法表列出常见的含糊写法和替换办法。

### G4 动作直接写成动词

不得写“进行、加以、予以、作出、开展”加动作名词，动作必须直接写成动词。

原因：这类结构让句子变长，还把动作藏进名词，读者要多想一步才知道做了什么。

- ✗ 对数据进行分析。
- ✓ 分析数据。
- ✗ 对配置作出调整。
- ✓ 调整配置。

### G5 程度词和模糊量词换成数字或具体事实

程度词和模糊量词必须换成数字或具体事实。常见的有“非常、极其、大量、显著、大幅、基本、一些、部分、若干、相关”。原文和上下文里没有这个数字或事实时，不得编造，必须写成“【待补：…】”。

原因：读者无法从“大量”知道是多少，也无法从“显著”知道变化有多大。编出来的数字会被读者当成事实。

- ✗ 显著缩短了加载时间。
- ✓ 加载时间从 3 秒缩短到 1 秒。
- ✓ 原文没有数据时：加载时间缩短了【待补：缩短前后的秒数】。
- ✗ 请准备相关材料。
- ✓ 请准备营业执照和法人身份证。

### G6 不用营销词和套话

不得使用营销词、行话和套话。删掉之后意思不变的词，必须删掉。常见的营销词有“赋能、一站式、无缝、极致、打造”；常见的行话有“沉淀、落地、对齐、闭环”；常见的套话有“值得注意的是、综上所述、众所周知”。

原因：这些词不增加信息。行话还要求读者先翻译成具体动作才能理解。

- ✗ 值得注意的是，该方案能无缝赋能各个业务线。
- ✓ 该方案适用于全部 4 条业务线，不用改现有流程。

### G7 不用口号句式

不得使用口号句式：“不是 X，而是 Y”这类对比宣言、对仗的金句、一环套一环的顶针句。对比的信息必须拆成两句平实的话。

原因：口号句式读着有气势，但没有说清事实。读者要的是机制、数字和依据。

- ✗ 交付的不是工具，而是结果。
- ✓ 交付物是每月一份数据报告和一份改进清单。

### G8 缩写和代号第一次出现时附全称或解释

缩写、产品代号、内部代号第一次出现时，必须附上全称或一句解释。不得自造缩写。

- ✗ 本周 CR 通过率下降。
- ✓ 本周代码评审（CR）的通过率从 80% 降到 65%。

## 句子

### G9 一句只讲一件事

一句必须只讲一件事。超过两个动作或两个判断时，必须拆成几句；三项以上的并列，必须写成列表。

原因：一句话塞进几件事，读者容易漏掉中间的那件。

- ✗ 上传文件后系统会检查格式并生成预览，同时通知审核人，审核通过后自动发布。
- ✓ 上传文件后，系统检查格式并生成预览。系统同时通知审核人。审核通过后，系统自动发布文件。

### G10 条件写在前面

条件宜写在前面：“如果……，……”“……时，……”。

原因：读者先知道条件，才能判断后面的内容是否适用于自己。

- ✗ 删除后其他人也打不开这个文件，如果文件已经共享。
- ✓ 如果文件已经共享，删除后其他人也打不开这个文件。

### G11 用主动句

宜用主动句。“被”字句只用在不需要说明是谁做的时候。

原因：主动句写清了谁做了什么。中文的“被”字句还常带不情愿、受损的意味。

- ✗ 配置被管理员修改了。
- ✓ 管理员修改了配置。

### G12 控制句子长度

一句话宜不超过 40 个字；操作步骤的一句宜不超过 30 个字。

说明：字数按汉字计，英文单词、数字各按一个字计。超过上限时，按 G9 拆句。

### G13 名词前的修饰语不超过 3 层

名词前的修饰语宜不超过 3 层。修饰语太长时，必须拆成主句加补充说明。

- ✗ 已配置好的高优先级每日自动同步任务失败了。
- ✓ 每日自动同步任务失败了。这个任务已配置好，优先级为高。

### G14 否定词和限定词不省略

否定词和限定词不得省略，也不得弱化：不、没、未、无、非、仅、只、除外。

原因：少一个“不”或“仅”，意思就反了或变宽了。压缩文字时最容易丢掉这类词。

- ✗ 管理员可以删除。（原意是只有管理员可以删除）
- ✓ 仅管理员可以删除。

### G15 保留表示把握程度和频率的词

表示把握程度和频率的词必须保留：可能、也许、大概、通常、偶尔、经常。没有把握的判断不得写成确定的结论。这些词是内容，不按 G5 删改。

原因：把握程度本身是内容。把“可能失败”改成“失败”，结论就变了。

- ✗ 请求失败是网络中断导致的。（实际只是推测）
- ✓ 请求失败可能是网络中断导致的。

### G16 代词只指上文里明确的名词

代词和指示代词（“它、这、该、其、此”）必须只指同一句或上一句里出现的名词。可能指两个以上的对象时，必须重复名词。

- ✗ 上传图片和视频后，系统会压缩它。
- ✓ 上传图片和视频后，系统会压缩图片。

## 内容

### G20 不写读者不需要的排除说明

排除说明是写明“没有什么、不做什么、不是什么”的话。读者想不到、也不影响读者做事的排除说明，不得写。读者可能误以为包含、因此会做错时，必须写。

常见的多余写法有三种：

- 括号里否认读者没想到的东西。
- 读者不知道有某个方案，正文却解释为什么没用这个方案。
- 结尾补一句自证，比如“已确认不含……”。

判断方法：删掉这句话，读者会不会因此做错一件事。不会，就删掉。

原因：排除说明让读者去想一件本来不存在的事。大模型写文字时，常把讨论里否掉的方案、没用到的选项写进正文。

说明：决策记录写明“为什么没选某个方案”，是这份记录要交代的内容，不算多余的说明。

- ✗ 午餐：西红柿炒鸡蛋（不放洋葱）。
- ✓ 午餐：西红柿炒鸡蛋。
- ✗ 本次改用 A 方案（没有用 B 方案）。
- ✓ 本次改用 A 方案。
- ✓ 报价 1200 元，不含税。（读者可能以为含税，所以要写）
